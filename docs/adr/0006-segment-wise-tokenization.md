# 0006. Segment-wise tokenization of the transcript

Status: Accepted, 2026-07-27.

## Context

The transcript that a tool-using agent produces is assembled from pieces with
different origins: a system prompt, a user prompt, tokens the policy sampled,
and tool results the environment returned. The natural implementation is to
build the whole string and tokenize it once. That is also the implementation
that destroys provenance.

BPE merges across whatever boundary they find. If a tool result ends in `}` and
the assistant header begins immediately after, a single token can cover the
last character of the environment's output and the first character of the
model's turn. There is then no answer to "was this token generated by the
model" that is both true and useful. Every downstream guarantee in ADR 0003
rests on that question having an exact answer.

There is a second, subtler failure. The teacher's privileged-context render
(ADR 0002, `AgentLoop.privileged_render`) prepends an oracle block to the same
transcript. Whole-string tokenization means the prepended text can change the
token boundaries of the shared content further along the sequence, so the
student's tokens and the teacher's tokens for the same text stop matching, and
the per-segment offset alignment has nothing to align.

## Decision

Every transcript segment is tokenized on its own and the resulting id lists are
concatenated. `TranscriptBuilder.add` in `src/miniverl/agent/transcript.py`
calls `tokenizer.encode(segment.text)` per segment and extends a flat id list;
segments that carry model-sampled ids are stored verbatim and never
re-tokenized at all.

Two consequences are load-bearing:

1. A token can never straddle a provenance boundary, so
   `model_generated_mask` is exact rather than approximate.
2. The teacher's render of a shared segment produces byte-identical token ids,
   which is what makes `build_alignment_map` able to check the alignment by
   comparing target token ids rather than trusting a computed offset. The
   privileged render copies each student span's ids directly
   (`token_ids=list(student.token_ids[span.start:span.end])`) and reuses its
   `segment_key`, so only the absolute positions shift.

Splitting a *sampled* token sequence at a text landmark is handled without
re-tokenizing, by `token_index_at_char`: it decodes growing prefixes of the
sampled ids until the decoded length reaches the landmark. When a token
straddles the landmark, the split is placed before that token, so the
straddling token joins the typed span (the tool call or the final answer)
rather than the untyped prefix. The stored sequence stays bit-identical to what
the policy produced.
`tests/unit/test_transcript.py::test_token_index_at_char_places_a_straddling_token_in_the_typed_span`
and `test_pretokenized_segments_are_stored_verbatim` pin both behaviours.

## Consequences

Positive:

- Provenance is exact, which is the precondition for everything in ADR 0003.
- Privileged-context alignment is checkable rather than assumed.
- The model is trained on exactly the token sequence it is later served,
  because inference builds the context through the same builder.
- The toy tokenizer is constructed so that concatenating segment encodings
  equals encoding the concatenation, so the toy backend exercises the same code
  path with no cross-boundary effects at all
  (`test_toy_tokenizer_has_no_cross_boundary_merges`).

Negative:

- **The token sequence is not the one a single `tokenizer(text)` call would
  produce.** Merges that would have spanned a segment boundary are lost, which
  costs a small number of extra tokens per turn. The size of that cost has not
  been measured for the Qwen tokenizer, and it grows with the number of turns
  because each turn adds boundaries.
- Those extra tokens cost context budget and decode time, and both are scarce
  here: `rollout.max_total_tokens` is 704 in the 16 GB recipe, and decode runs
  at roughly 11 to 13 tok/s on this machine.
- A perplexity computed on a miniVERL transcript is not directly comparable to
  one computed on a whole-string tokenization of the same text.
- Every segment must be non-empty. `TranscriptBuilder.add` raises on a segment
  that tokenizes to zero tokens, which makes some otherwise reasonable
  formatting choices illegal.

The trade is stated in the module docstring and accepted deliberately:
provenance exactness beats a handful of saved tokens.

## Alternatives considered

**Tokenize the whole string, then map character offsets back to tokens.**
Rejected: the mapping is ambiguous exactly at the boundaries that matter, and
the ambiguity is resolved by rounding, which means the provenance mask becomes
approximate. It also breaks the privileged-context render.

**Tokenize the whole string, and only mark tokens fully inside a model span.**
Rejected: it silently drops the first and last supervised token of each turn,
which for short tool-call payloads is a large fraction of the critical tokens.

**Force a boundary-safe format (always end segments on a token that cannot
merge).** Rejected as fragile: it is a property of the tokenizer, not of the
format, and it would have to be re-verified for every new model family.
